# اختبارات E2E — ChatE

هذا المجلد توثيق لطبقة اختبار الواجهة من طرف إلى طرف. لا يوجد في المستودع اعتماد Playwright، ولا يُضاف: الأداة القابلة للتشغيل موجودة في `scripts/qa/` وتعمل على Chrome DevTools Protocol مباشرة (Node 24 + Chrome النظامي).

## كيف تعمل

1. `scripts/qa/seed.mjs` يزرع مستخدمي اختبار في قاعدة QA ويوقّع كوكي الجلسة.
2. `scripts/qa/run-e2e.mjs` يُنفّذ فحوص API/الرؤوس أولًا ثم رحلة متصفح كاملة، ويكتب مصفوفة PASS/FAIL/BLOCKED وإثباتات console/network ولقطات.
3. `scripts/qa/lib/cdp.mjs` هو المحرّك: إطلاق Chrome، اتصال WebSocket بـ CDP، تنقّل/نقر/كتابة/تنقّل لوحة مفاتيح/لقطات، وجمع أخطاء console والشبكة.

## التغطية الحالية

- الصفحة الرئيسية، التنقّل، الخصوصية، الشروط، الحساب، السجل، 404، رفض الإدارة.
- إعادة توجيه `/workspace` لغير المسجّل، ومساحة العمل بعد تسجيل الدخول، والاختصارات، والتحقق من السؤال الفارغ، وبوابة الجوال، ورسالة الخطأ العربية.
- تبديل المظهر والتحقق من بقاء الكوكي بعد إعادة التحميل، والرجوع/التقدّم في المتصفح.
- RTL، وتسلسل التركيز بلوحة المفاتيح، وأساسيات الوصول (تسميات، alt، عنوان h1 واحد، تباين).
- استجابات 390×844 و768×1024، والوضع الداكن.
- عقد API: 401/403/404/422، رؤوس الأمان، فحص تسرّب الأسرار، CSRF/Origin للإدارة، توقيع الجلسة المزوّر، دورة OTP (إرسال/رمز خاطئ/تحقق/إعادة استخدام).
- رحلة المقارنة الكاملة على خادم mock: 3 نماذج مجانية تنجح وHaiku يفشل مستقلًا، مع polling.

## التشغيل

```powershell
$env:QA_BASE_URL='http://chate.test:3212'
$env:QA_ENV_FILE='tmp/qa/e2e.env'
$env:QA_PHASE='prod-mock'
$env:QA_GOOGLE_STUB='1'
& C:\Pak\node.exe scripts/qa/run-e2e.mjs
```

## اصطلاحات

- **PASS**: تحقّق السلوك المتوقّع فعليًا.
- **FAIL**: مخالفة سلوكية أو عيب مؤكّد؛ يُرفق الاستثناء برسالة عربية وإعادة إنتاج.
- **BLOCKED**: تعذّر التحقق في هذه البيئة (مثل توقّف الخادم أو غياب سر تشغيل)، مع سبب صريح.
- **SKIP**: فحص لا ينطبق على هذه المرحلة (مثال: رمز Google غير مهيأ).
