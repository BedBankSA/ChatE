## 2) Temporary public demo — reproducible, not durable

**Why a tunnel:** no hosting-account credential (VPS, Vercel, Netlify, Cloudflare account) exists in this environment. GitHub CLI is authenticated only as a repository user; that is not a hosting account. A Cloudflare quick tunnel needs no account and is the only honest way here to put this exact production build on a public HTTPS URL. The durable VPS path stays owner-gated (§5).

**Run it (from the repository root, Windows):**

```powershell
# add -Build after code changes so the public demo serves the current source
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy\public-demo.ps1 -Build

# inspect the URL, then stop the server and tunnel recorded by the run
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy\public-demo.ps1 -Stop
```

**What the run does:** loads `.env.local` into the child environment without printing values; builds if `.next/BUILD_ID` is missing (or `-Build`); starts `next start` on `127.0.0.1:3223`; downloads `cloudflared.exe` into `.tools/` only if absent; starts a quick tunnel; probes the public origin and the local server; writes `docs/evidence/public-deployment.md`; prints what is still running and how to stop it. It never records secret values.

**What a PASS proves:**

- The production build serves the Arabic RTL landing page, `/privacy`, `/terms` over public HTTPS through the Cloudflare edge.
- `GET /api/models` returns 200 with `"ok":true` from the public origin.
- Security headers reach the public response: HSTS, CSP without `unsafe-eval`, `X-Frame-Options: DENY`, `nosniff`, COOP, no `X-Powered-By`.
- Anonymous API access stays closed (admin 401, comparisons 401, history 401/absent, uploads 401/403).

**What a PASS does NOT prove (and why it must not be cited as production):**

- **No durable hosting.** Quick tunnels are ephemeral, have no SLA, and the URL dies with `cloudflared`. No domain, no DNS ownership, no certificate management.
- **Google sign-in will not work on the demo origin.** `NEXT_PUBLIC_GOOGLE_CLIENT_ID` is baked into the client bundle at build time, and a `trycloudflare.com` hostname is not an authorized JavaScript origin; `APP_URL` also does not match the demo origin.
- **Turnstile-gated flows fail closed on the demo origin.** `.env.local` lists `localhost,127.0.0.1` in `TURNSTILE_EXPECTED_HOSTNAMES`, which production mode rejects by design (`TURNSTILE_LOCALHOST`, 503); the throwaway hostname is not registered on the widget either. Uploads/OTP/sign-in interactions therefore cannot complete there.
- **No end-to-end product run.** Uploads → comparison → history and live provider calls need a signed-in, phone-verified session; those are covered (or not) by separate verification evidence, not by this demo.
- **No load, uptime, monitoring, or provider-spend evidence.**
- **Not a VPS execution.** The deploy bundle under `deploy/` stays review-only until the owner runs the runbook on a real server.

**Known environment caveats:** the first run downloads about 55 MB of `cloudflared` into `.tools/` (gitignored); the run needs outbound access to GitHub and Cloudflare; `.env.local` fileserver secrets stay on this machine and are only inherited by the local server process; use `-Port` if 3223 is taken.

## 3) CI — what a green run will prove

**Workflow:** `.github/workflows/ci.yml`, name `CI`, triggers: push to `main`, pull request to `main`, manual `workflow_dispatch`. `ubuntu-latest`, Node 24, npm cache keyed by `package-lock.json`, `permissions: contents: read`, `concurrency` group per workflow/ref with `cancel-in-progress: true`.

**Steps:** `npm ci` → `next typegen` → `npm run typecheck` → `npm run lint` → `npm test` → `npm run build` → `npm run check:bundle`.

**No secrets:** only dummy public values are set for the build (`APP_URL`, `NEXT_PUBLIC_GOOGLE_CLIENT_ID`, `NEXT_PUBLIC_TURNSTILE_SITE_KEY`). These are public by design and are inlined into the browser bundle; real provider/session secrets stay out of CI.

**What a green run would prove:** the committed tree installs reproducibly, typechecks, lints, passes the Vitest suite, builds for production with placeholder public env, and no server-secret name/value leaked into `.next/static`.

**What it would not prove:** a deployed server, live providers, SMS OTP, browser E2E, dependency-CVE triage (`npm audit` is not wired), or load capacity.

**Status:** workflow authored and YAML-validated locally (2026-10-28). **First execution is pending** push/PR by the Lead/owner. Check with `gh run list --repo BedBankSA/ChatE --limit 5`.

## 6) Honesty rules for this evidence set

1. Never call a quick-tunnel URL a "production deployment" or cite it as uptime/hosting evidence.
2. Never call a green CI run a deployment.
3. Never claim VPS/TLS/domain/Cloudflare execution without the server-side commands in the runbook.
4. Never write secret values into evidence files; `.env.local` values are only inherited by local child processes, and the demo tool prints counts/names, not values.
5. Provider calls, SMS delivery, uploads/quotas, and browser E2E are separate evidence sets; do not merge them into this file's claims.
