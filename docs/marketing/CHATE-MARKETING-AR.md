## English Executive Summary

ChatE is an Arabic-first web application that sends one question to several AI models and renders the answers side by side. The code supports a 23-model server catalog of which 10 are marked available: eight free OpenRouter chat/answer models (Gemma 4 31B, Flint, Gemma 4 26B A4B, Xing4.0, North Mini Code, Mammoth-1, Elephant-1, Span-01 Lite), the `openrouter/free` router, and Anthropic's Claude Haiku 5.5. The verified product surface includes an RTL Arabic UI with Arabic-first instructions, Google Identity Services sign-in (ID-token + nonce flow, no client secret), Cloudflare Turnstile in interaction-only/execute mode, atomic per-provider quota reservation with idempotency and 429 retries, SQLite single-file storage, an authenticated admin dashboard with counters and user controls, security headers (CSP, HSTS in production), and a deliberate policy that only `:free` OpenRouter routes and one paid Anthropic model can ever be called. The test suite is green: 14 files and 141 tests passed (`npm test`, 2026-10-28 16:37), after session-hardening, OTP-route and Haiku opt-in changes landed. No live provider call was made by the tests.

The product is **not launch-ready for the public**. File uploads are a stub: the picker posts file names only, `POST /api/uploads` gates Turnstile and then returns 401 without storing bytes, and comparison creation always passes `attachments: []`. The OTP send/verify flow has now been implemented in this release (routes, UI, and route tests), but it needs a real SMS provider in the environment (`OTP_PROVIDER=http`, `OTP_HTTP_URL`, plus `OTP_PEPPER` or `SESSION_SECRET`); no live SMS was sent in this audit, so phone verification must not be claimed as working. Because the phone gate blocks model usage, a new user still cannot currently submit a comparison end to end. `/history` is static text, there is no billing code, no analytics SDK, no public deployment, no selected license (the GitHub repository is public with no license), and no live provider call has been recorded anywhere in the repository or by this audit. Haiku live calls are off by default and require the operator to set `HAIKU_LIVE_CALLS=1` (`src/domain/models/haiku.ts:6-14`), so "tested live" must not be claimed.

Recommendation: a 30-day **invite-only Arabic private beta**, gated on three readiness items — end-to-end phone verification, comparison history persistence, and one owner-approved live provider smoke test — followed by a public launch only after a deployment, a license, and honest upload/history messaging are in place. Lead the market message with the comparison/verification loop (one question, independent answers, visible provider/effort), not with file support, scale, or linguistic superiority. Every claim in this package carries an evidence tag; the binding ledger is `docs/marketing/CLAIMS-AND-EVIDENCE.md`.

## 1. الملخص التنفيذي

ChatE منتج ويب عربي يحاول حل مشكلة بسيطة يعيشها كل من يستخدم الذكاء الاصطناعي بالعربية: **أي نموذج أجاب أفضل؟** بدل أن يفتح المستخدم أربع نوافذ ويلصق السؤال أربع مرات ويقارن يدويًا، يكتب السؤال مرة واحدة، يختار حتى ثمانية نماذج، ويرى الإجابات جنبًا إلى جنب كلما وصلت، مع اسم النموذج والجهد المرسل والزمن والتكلفة التقديرية عند توفرها `[مُتحقق]` (`src/components/workspace.tsx:245-260`، `src/domain/comparison/input.ts:23`).

المنتج ليس «تطبيق محادثة عربيًا آخر». الفرق الجوهري أنه **مقارنة مستقلة**: السؤال نفسه والتعليمات الأساسية نفسها لكل نموذج، ولا يرى نموذج إجابة منافس، وفشل نموذج واحد لا يوقف البقية `[مُتحقق]` (`src/domain/comparison/plan.ts:7-8`، `src/server/comparisons/execute.ts:50`، `docs/architecture.md:24-32`). هذه الخاصية تعطي المستخدم شيئًا لا تعطيه المساعدات العامة: **دليلًا على الاختيار** بدل رأي واحد.

البنية التحتية المسجلة في الكود تسمح بذلك على نطاق صغير ومحكوم `[مُتحقق]`: سجل نماذج مركزي من 23 نموذجًا، 10 منها فقط مسموح لها بالمرور، وجميع نقاط OpenRouter مجانية تنتهي بـ `:free`، وClaude Haiku 5.5 هو النموذج المدفوع الوحيد، بجهد `medium` وتفكير `adaptive` وبلا معاملات معاينة (`src/domain/models/catalog.ts:92-773`، `src/domain/models/dispatch.ts:53-55`، `src/domain/models/haiku.ts:5-6`). الحصص تُحجز ذريًا لكل مزود قبل أي إرسال، مفتاح idempotency يمنع التكرار، و429 يُعاد مرتين كحد أقصى `[مُتحقق]` (`src/domain/quota/reserve.ts:14-39`، `src/server/db/quota.ts:41-48`، `docs/architecture.md:34-36`).

لكن **الفجوة بين «الكود موجود» و«المنتج يعمل» كبيرة، ويجب أن تكون هذه الفجوة هي محور خطة التسويق لا هامشها**:

- **الرفع غير مكتمل** `[مُتحقق]`: واجهة الاختيار ترسل أسماء الملفات فقط إلى `POST /api/uploads`، والمسار يتحقق من Turnstile ثم يعيد 401 ولا يخزن بايتات، وإنشاء المقارنة يمرر `attachments: []` (`src/components/workspace.tsx:159-172`، `src/app/api/uploads/route.ts:4-8`، `src/server/comparisons/handle.ts:41`). ملاحظة دقيقة: طلب بلا رمز Turnstile يعيد 403 «تعذر التحقق الأمني»، وبعد رمز صحيح يعيد 401 «يلزم تسجيل الدخول»؛ في الحالتين لا تخزين.
- **التحقق بالجوال مبني لكن غير مثبت حيًا** `[جزئي]`: أُضيف في هذا الإصدار تدفق إرسال وتحقق فعلي (`src/app/api/otp/send/route.ts`، `src/app/api/otp/verify/route.ts`، `src/components/otp-request.tsx`، `tests/otp-route.test.ts`)، لكنه يحتاج مزود رسائل في بيئة التشغيل (`OTP_PROVIDER=http` + `OTP_HTTP_URL` + `OTP_PEPPER` أو `SESSION_SECRET`)، ولم يُرسل رمز SMS حي في هذه البيئة. بوابة النماذج تمنع الإرسال قبل توثيق الجوال (`src/domain/auth/model-gate.ts:19-21`)، لذا تبقى الحلقة مقطوعة لمستخدم جديد حتى يُهيأ المزود ويُثبت التدفق حيًا.
- **لا سجل مقارنات حقيقي** `[مُتحقق]`: صفحة `/history` نص توضيحي ثابت ولا تعرض صفوفًا (`src/app/history/page.tsx:4-15`، `README.md:9`).
- **لا نشر عام ولا ترخيص** `[مُتحقق]`: README يصرح بعدم وجود نشر عام (`README.md:119`)، والبيلد يُشغَّل محليًا فقط، وملف الترخيص غير موجود. مستودع GitHub **عام** (`https://api.github.com/repos/BedBankSA/ChatE`: `private=false`، `license=null`، 0 نجوم، تاريخ الإنشاء 2026-10-27).
- **لا دليل على نجاح استدعاء حي** `[مُتحقق]`: الوثائق تقول صراحةً إنه لم يُرَ اختبار حي لـ OpenRouter أو Anthropic (`README.md:120`، `docs/test-results.md:3`). أصبح استدعاء Haiku الحي معطّلًا افتراضيًا ويشترط `HAIKU_LIVE_CALLS=1` من المشغّل (`src/domain/models/haiku.ts:6-14`)، وهذا يتسق الآن مع نفي الوثائق أي استدعاء حي؛ لكن لا يوجد سجل استدعاء ناجح، فلا يجوز ادعاء «مختبر حيًا».

الخلاصة التسويقية: **لدينا منتج مقارنة عربي أولًا متماسك في الكود، وليس لدينا بعد منتج قابل للاستخدام العام.** لذلك الخطة الموصى بها هي بيتا مغلقة بدعوة، بشرط استكمال ثلاثة عناصر (التحقق بالجوال، حفظ السجل، اختبار حي واحد بموافقة المالك)، ثم إطلاق عام بعد النشر والترخيص وتصحيح الرسائل. أي حملة «جرّبه الآن» قبل ذلك ستنتج مستخدمين يصلون إلى شاشة لا تعمل، وهو أسوأ من التأجيل.

## 2. المشكلة

### 2.1 المشكلة الأولى: العربية متأخرة في الويب، لا في الاستخدام

اللغة العربية مستخدمة على نطاق واسع، لكن حضورها في محتوى الويب ضعيف جدًا. حسب إحصاء W3Techs المنشور في 28 أكتوبر 2026، الإنجليزية هي لغة محتوى 49.5% من المواقع، بينما العربية 0.6% فقط من المواقع التي تُعرف لغتها `[مُتحقق — مصدر خارجي]` (W3Techs، `https://w3techs.com/technologies/overview/content_language`). الفارق ليس تفصيلًا تقنيًا: النماذج تُقيَّم وتُكتب تعليماتها وتُبنى أدواتها حول الإنجليزية أولًا، فيظهر أثر ذلك في جودة الاستدعاء العربي وتجربة الواجهة العربية.

الاستنتاج التسويقي المباشر: **لا نبيع «ذكاءً اصطناعيًا بالعربية» كأننا صنعناه، ولا نبيع تفوقًا لغويًا لم نقسه.** نبيع **طبقة اختيار ومقارنة** تساعد المستخدم العربي على اختيار النموذج الأنسب لسؤاله، بغض النظر عن مزوّده. هذا ادعاء يمكن إثباته من الكود اليوم، بخلاف ادعاء «أفضل نموذج عربي» الذي لا يملك أحد في هذا المستودع دليلًا عليه.

### 2.2 المشكلة الثانية: تعدد النماذج صار عبئًا على المستخدم

المستخدم اليوم يواجه عشرات النماذج في قوائم واحدة، بأسماء متشابهة وأسعار وحدود سياق مختلفة. عندما يكتب سؤالًا مهمًا (مراجعة عقد، اختيار تصميم، تشخيص خطأ برمجي، تلخيص بحث)، لا توجد طريقة سريعة لمعرفة أي نموذج أعطى إجابة أفضل لسؤاله تحديدًا. الطرق الحالية:

1. يفتح عدة مساعدات ويلصق السؤال في كل واحد يدويًا، ثم يقارن بصريًا. مكلف وقتًا ومربك.
2. يستخدم منصة مقارنة عالمية بالإنجليزية (أرينا أو ما شابه)، لكن تجربة الواجهة ليست عربية، وقد لا تناسب سؤاله أو ملفه.
3. يختار نموذجًا واحدًا ويتعوّد عليه، فيفقد فرصة معرفة أن نموذجًا آخر كان أدق في هذه الحالة.

ChatE يعالج الحالة الأولى والثالثة: يلصق السؤال مرة واحدة ويحصل على أعمدة مستقلة، مع تمييز واضح بين النماذج المقيدة والمتاحة (`src/components/workspace.tsx:222-236`) وحالات عربية مفهومة: «في الانتظار»، «يعمل الآن»، «اكتمل»، «النتيجة ناقصة»، «موقوف حسب شروط المزود»، «غير مناسب لهذا الطلب»، «يتجاوز السياق» `[مُتحقق]` (`src/domain/comparison/view.ts:21-32`).

### 2.3 المشكلة الثالثة: الثقة والخصوصية

من يجرّب أدوات ذكاء اصطناعي عربية يخشى أمرين: (أ) أين يذهب سؤاله؟ (ب) من يدفع ثمن الاستدعاء وهل يمكن أن يُستغل؟ ChatE يبني موقفًا قابلًا للتسويق، لكنه موقف محدود يجب وصفه بدقة `[مُتحقق]`:

- المتصفح لا يستدعي OpenRouter ولا Anthropic؛ المفاتيح على الخادم فقط (`README.md:5`، `docs/architecture.md:3`).
- التسجيل عبر زر Google الرسمي (Google Identity Services)، بلا كلمات مرور وبلا سر عميل في تدفق رمز الهوية (`README.md:13`، `src/components/google-intent.tsx:7-8`).
- الجلسة في كوكي `HttpOnly` و`SameSite=lax` و`Secure` عند HTTPS، ومدة 14 يومًا `[مُتحقق]` (`src/domain/auth/session.ts:49-54`، `src/app/api/auth/google/route.ts:80`).
- حماية Turnstile شرط لبدء الدخول ورفع الملفات وطلب رمز الجوال وإنشاء المقارنة، وتُتحقق مرة واحدة (`README.md:13`، `src/components/turnstile.ts:78-89`، `src/server/comparisons/handle.ts:33-34`).
- خط أساس أمني في الترويسات: CSP، `X-Frame-Options: DENY`، `nosniff`، `Referrer-Policy`، وHSTS في الإنتاج `[مُتحقق]` (`src/domain/security/headers.ts:21-35`).

هذا يسمح بجملة تسويقية صادقة: «مفاتيح المزودين لا تصل إلى متصفحك، ودخولك عبر Google، وما يُرسل هو سؤالك إلى النماذج التي اخترتها». ولا يسمح بجملة «بياناتك لا تغادر جهازك» أو «تشفير من الطرف إلى الطرف» — لأنها غير صحيحة.

## 3. الجمهور المستهدف (ICP)

### 3.1 الشريحة الأساسية: «المستخدم العربي الجاد للذكاء الاصطناعي»

التعريف التشغيلي `[افتراض، مبني على بنية المنتج]`: شخص يكتب بالعربية ويستخدم نماذج LLM أسبوعيًا على الأقل في عمل أو دراسة، ولديه حساسية لاختيار النموذج (لأنه يدفع أو لأن جودة الإجابة تهمه)، ويفضّل أداة عربية الواجهة. الخصائص:

- **اللغة:** العربية لغته الأولى، ويقرأ الإنجليزية بدرجة كافية لاستخدام أدوات عالمية لكنه يفضّل العربية في الواجهة.
- **السلوك:** يجرّب أكثر من مساعد، يقرأ مقارنات، يهتم بالخصوصية والحدود المجانية.
- **القيمة المطلوبة:** توفير وقت المقارنة اليدوية + شفافية اسم النموذج والجهد + حدود واضحة لما هو مجاني.

### 3.2 الشرائح الثانوية

1. **الطلاب والباحثون العرب** `[افتراض]`: مقارنة شروح وتلخيصات وتوليد أسئلة بحثية عبر نماذج متعددة، مع حساسية للتكلفة. الحصة المجانية عامل جذب قوي، والجوال شرط تحقق قد يكون حاجزًا يجب إدارته.
2. **صنّاع المحتوى والمسوقون** `[افتراض]`: مقارنة صياغات إعلانية أو عناوين عبر نماذج، واختيار النبرة الأنسب. هذه الشريحة تتحمل حاجز التحقق بالجوال أكثر من الطلاب، وهي الأقرب للدفع لاحقًا.
3. **المطورون وفرق المنتج الصغيرة** `[افتراض]`: تقييم سريع لنماذج مجانية قبل بناء تكامل، مع الاهتمام بمعرّفات النماذج وحدود السياق. سجل النماذج في `GET /api/models` يقدم بيانات سياق وإتاحة (`src/domain/models/catalog.ts:785-825`) وهو مفيد لهم حتى لو لم يستخدموا الواجهة.
4. **المؤسسات الصغيرة والمكاتب المهنية في الخليج** `[افتراض، عالي الاحتياج للتحقق]`: تحتاج أداة داخلية لمقارنة إجابات النماذج على أسئلة عمل، مع متطلبات خصوصية أعلى. هذه الشريحة لا تُخاطب اليوم لأن الإنتاج والنشر والترخيص غير موجودة.

### 3.3 خارج النطاق (Anti-personas)

- من يريد محادثة متعددة الجولات أو ذاكرة طويلة: المنتج يصرح بأنه ليس سجل محادثة متعدد الجولات (`README.md:9`).
- من يريد تطبيق جوال أصلي: المنتج ويب فقط، والمواصفة الملزمة تستبعد تطبيقات الجوال (`docs/binding-specs.md:21`).
- من يريد واجهة API للمطورين: لا توجد واجهة API عامة موثقة أو مفاتيح للمستخدمين؛ ما يوجد مسارات داخلية للتطبيق.
- من يريد رفع ملفات اليوم: غير مدعوم فعليًا، وسيُحال إلى خارطة الطريق.

### 3.4 التوزيع الجغرافي

الأولوية الخليج ومصر والشام والمغرب العربي، بحسب سهولة الوصول إلى مجتمعات تقنية عربية ومعرفة Google/Turnstile `[افتراض]`. اللغة هي معيار التقسيم الأول، لا البلد.

## 4. الشخصيات

### 4.1 سارة — طالبة ماجستير في السياسات العامة (الرياض)

- **العمر/السياق:** 24 سنة، تكتب بحثًا بالعربية والإنجليزية، تستخدم ChatGPT وGemini أسبوعيًا.
- **الألم:** تحتاج تلخيص 12 ورقة أكاديمية؛ تجرب نموذجًا واحدًا وتخشى أن يكون فهمه للنص العربي أضعف من غيره، ولا وقت لديها للمقارنة اليدوية.
- **ماذا تريد:** إجابة واحدة موثوقة + معرفة أي نموذج كان أفضل لهذا النص.
- **كيف يخدمها ChatE:** سؤال واحد، حتى 8 نماذج، أعمدة متجاورة، حالة عربية لكل نموذج `[مُتحقق في الكود]`.
- **ما يعوقها اليوم:** التحقق بالجوال يحتاج مزود SMS وإثباتًا حيًا، والرفع غير مكتمل `[مُتحقق]`. لذلك لا تُستهدف بحملة «جرّبي الآن» قبل الإصلاح؛ تُستهدف بقائمة انتظار ورسالة «نفتح تدريجيًا».

### 4.2 خالد — مطور مستقل (عمّان)

- **السياق:** 31 سنة، يبني أدوات صغيرة، يستخدم نماذج مجانية عبر OpenRouter، حساس للتكلفة والحدود.
- **الألم:** يريد معرفة أي نموذج مجاني يعطي أفضل كود لسؤاله، ويكره أن يستبدل المزوّد النموذج بصمت أو يمرر طلبًا مدفوعًا.
- **كيف يخدمه ChatE:** سياسة صارمة: OpenRouter مجاني فقط، رفض أي معرف لا ينتهي بـ `:free`، ورفض أي طلب يحتوي `models` أو `provider`، وعرض معرّف النموذج والجهد المرسل `[مُتحقق]` (`src/domain/models/dispatch.ts:53-58`، `src/domain/comparison/plan.ts:160-167`، `src/components/workspace.tsx:248-253`).
- **ما يعوقه:** لا نشر عام، والتحقق بالجوال؛ ويريد أيضًا رؤية سجل مقارنات محفوظ.

### 4.3 ليلى — مسؤولة محتوى في وكالة (دبي)

- **السياق:** 29 سنة، تكتب إعلانات عربية، تجرّب صياغات متعددة، تدفع لأدوات كتابة.
- **الألم:** تحتاج مقارنة نبرات وصياغات بين نماذج قبل اختيار النسخة النهائية؛ الوقت هو التكلفة الحقيقية.
- **كيف يخدمها ChatE:** مقارنة سريعة، شفافية الزمن والتكلفة التقديرية، ومقارنة «أقصى إعدادات كل نموذج» المعروضة في الواجهة `[مُتحقق]` (`src/components/workspace.tsx:189`، `docs/max-quality-free-policy.md:266-277`).
- **ما يعوقها:** لا حفظ سجل، ولا تصدير، ولا حساب فريق. هذه فرص roadmap لا تُسوَّق اليوم.

## 5. عرض القيمة

### 5.1 الصيغة الأساسية

**«سؤال واحد. عدة نماذج. إجابات متعددة... وقرار أوضح.»**

هذه ليست شعارًا فقط: كل جزء منها قابل للتتبع في الكود `[مُتحقق]`:

- «سؤال واحد»: حقل سؤال واحد يذهب إلى كل النماذج المختارة (`src/components/workspace.tsx:192-195`).
- «عدة نماذج»: حتى 8 نماذج في المقارنة الواحدة (`src/domain/comparison/input.ts:23`).

### 5.2 الركائز الثلاث (Message Pillars)

1. **المقارنة المستقلة بدل الاختيار الأعمى.** السؤال نفسه لكل نموذج، ولا يرى نموذج إجابة منافس، وفشل واحد لا يوقف البقية `[مُتحقق]`. الدليل: `src/domain/comparison/plan.ts:7-8`، `src/domain/comparison/plan.ts:292-297`، `src/server/comparisons/execute.ts:50`.

3. **سياسة مجانية صارمة بلا فخ مفاجئ.** لا تحويل تلقائي إلى نموذج مدفوع، ولا استبدال صامت، ولا مسار OpenRouter مدفوع؛ Haiku اختيار ظاهر ومحاسبة منفصلة `[مُتحقق]`. الدليل: `src/domain/models/dispatch.ts:53-55`، `README.md:93-97`، `docs/binding-specs.md:55-57`.

## 6. الموضع (Positioning)

### 6.1 بيان الموضع

**لمن:** العربي الذي يستخدم نماذج الذكاء الاصطناعي بانتظام ويحتاج اختيار النموذج الأنسب لسؤاله.
**ChatE هو:** تطبيق ويب عربي لمقارنة إجابات عدة نماذج على سؤال واحد، بواجهة RTL وشفافية في النموذج والجهد والتكلفة.
**بخلاف:** المساعدات العامة التي تعطي إجابة واحدة، ومنصات المقارنة العالمية الإنجليزية، وواجهات API التي تتطلب معرفة تقنية.
**لأن:** المقارنة المستقلة + شفافية ما يُرسل + سياسة مجانية صارمة تعطي قرارًا أوضح بجهد أقل، والواجهة العربية تلغي حاجز اللغة في أداة القرار نفسها.
**فقط بعد:** استكمال التحقق بالجوال والنشر والترخيص — الموضع **طموح مقصود**، وليس وعدًا بحالة تشغيل اليوم.

### 6.2 الفئة (Category)

الفئة التي ننافس فيها هي **أدوات مقارنة/اختيار النماذج للمستخدم النهائي**، لا فئة «المحادثة العامة». هذا اختيار مقصود: في فئة المحادثة، المنافسون أكبر وأسرع ومجانيون؛ وفي فئة المقارنة، الفرق قابل للإثبات من الكود، والمستخدم يجد سببًا للعودة (سؤال جديد = مقارنة جديدة).

### 6.3 محاور التمايز

1. **عربي أولًا حقيقي:** `lang="ar" dir="rtl"` وخط IBM Plex Sans Arabic وتعليمات أساسية «أجب بلغة السؤال» `[مُتحقق]` (`src/app/layout.tsx:9-28`، `src/domain/comparison/plan.ts:7-8`).
2. **حدود صريحة:** 23 نموذجًا في السجل، 10 متاحة فقط، و13 تظهر بحالة «مقيد بشروط المزود» بدل إخفائها أو الادعاء بها `[مُتحقق]` (`src/domain/models/catalog.ts` + فحص `GET /api/models` أعاد 23/10/13).
3. **Haiku بجهد ثابت وشفاف:** `thinking.type=adaptive` و`output_config.effort=medium`، ورفض أي `temperature/top_p/top_k` `[مُتحقق]` (`src/domain/models/haiku.ts:28-46`).
4. **مقارنة بأقصى إعدادات كل نموذج:** بناء الطلبات من بيانات السجل وسياسة `MAX_QUALITY_FREE` `[مُتحقق]` (`docs/max-quality-free-policy.md:1-18`، `src/domain/models/catalog.ts:46-47`).
5. **إدارة وحصص قابلة للتشغيل:** حجز ذري، idempotency، إعادة محاولة 429، لوحة إدارة بلا نص أسئلة المستخدمين `[مُتحقق]` (`src/domain/quota/reserve.ts`، `README.md:117`).

## 8. حلقة الاستخدام (Funnel)

### 8.1 الحلقة المستهدفة (بعد اكتمال المتطلبات)

1. **الهبوط:** صفحة رئيسية عربية بعنوان «سؤال واحد. إجابات متعددة...» وزر Google `[مُتحقق]` (`src/app/page.tsx:8-20`).
2. **الدخول:** زر Google الرسمي، Turnstile خلف الكواليس، جلسة HttpOnly `[مُتحقق]`.
3. **إكمال الملف:** الاسم والبريد من Google للقراءة فقط؛ الجوال مطلوب ويُوحَّد إلى E.164 `[مُتحقق في النص/الكود]` (`account/page.tsx:10`، `docs/binding-specs.md:36`).
4. **بوابة الجوال:** لا إرسال نموذج قبل التحقق — التدفق مبني، لكنه معطّل عمليًا في هذه البيئة لعدم تهيئة مزود الرسائل وعدم إثباته حيًا `[مُتحقق]`.
5. **مساحة العمل:** سؤال واحد، 4 اختصارات (محادثة/برمجة/خفيف/مقارنة)، اختيار نماذج من 23 `[مُتحقق]` (`workspace.tsx:215-236`).
6. **الإرسال:** Turnstile مرة واحدة + حجز حصة + إنشاء مقارنة + جدولة تنفيذ `[مُتحقق]` (`handle.ts:33-86`).
7. **المتابعة:** استقصاء `GET /api/comparisons/{id}` كل 1.2 ثانية، توقف بعد ثلاث محاولات فاشلة متتالية `[مُتحقق]` (`workspace.tsx:101-120`).
8. **النتيجة:** أعمدة مستقلة، حالات عربية، زمن وتكلفة تقديرية `[مُتحقق]`.
9. **العودة (المفقودة):** لا حفظ سجل ولا إعادة استخدام سؤال. هذه أكبر فجوة احتفاظ، وتُعالج في خارطة الطريق.

### 8.2 تحليل الاحتكاك الحالي

| الخطوة | الاحتكاك | الأثر | حالة |

| الدخول | يجب تسجيل Google؛ لا وضع ضيف | يقلل التسرب لكنه يمنع التجربة السريعة | `[مُتحقق]` |

### 8.3 رحلة «الوقت إلى القيمة»

الهدف `[افتراض]`: من الوصول إلى أول نتيجة مقارنة في أقل من 3 دقائق. المسار الحالي يمنع ذلك لسببين: (أ) الجوال، (ب) زمن النماذج المجانية. بعد الإصلاح، القياس يجب أن يكون: زمن الدخول + زمن إكمال الملف + زمن أول نتيجة. لا توجد اليوم أداة قياس تحليلات في الكود، لذا القياس سيكون يدويًا/إداريًا حتى يُضاف.

- **طريقة الحساب:** المقارنة إلى N نموذج OpenRouter تحجز N وحدة؛ Haiku يُحجز على حساب `anthropic` منفصل ولا يُسحب من رصيد OpenRouter `[مُتحقق]` (`src/server/comparisons/store.ts:34-46,265-269,336-338`، `README.md:97`).
- **المحاسبة:** التكلفة التقديرية تظهر في الواجهة عند حسابها (`workspace.tsx:257`)، وتكلفة Haiku تُحسب بالسعر الموثق (`haiku.ts:48-64`).

### 9.2 اقتصاديات الوحدة (تقديرية وموسومة)

**Haiku 5.5:** الإدخال $0.10/مليون رمز حتى 100 ألف رمز في الطلب، والإخراج $0.50/مليون، وفوق العتبة $0.50/$2.50 `[مُتحقق — من الوثائق الرسمية المقروءة]` (`docs/haiku-5-5-addendum.md:93-104`).

مثال افتراضي `[افتراض]`: طلب Haiku بـ 1,000 رمز إدخال + 1,000 رمز إخراج ≈ $0.0001 + $0.0005 = **$0.0006** لكل استدعاء (دون ذاكرة مؤقتة). لا يوجد قياس استخدام فعلي في المستودع؛ هذه حسابات سعرية لا فاتورة.

**OpenRouter المجاني:** النقاط في السجل الحي كانت بسعر إدخال/إخراج `"0"` `[مُتحقق — لقطة 2026-10-27]` (`docs/openrouter-model-registry.md:27`)، لكن حدود المنصة لنماذج `:free` هي 20 طلبًا/دقيقة، و50 طلبًا/يومًا للاعتمادات الأقل من 10، أو 1000 طلب/يوم للاعتمادات 10 فأكثر `[مُتحقق — من وثائق OpenRouter المقروءة]` (`docs/openrouter-model-registry.md:43-52`). **هذا الحد هو القيد التشغيلي الحقيقي، وليس رقم الحصة في المتغيرات.** الحصة المشتركة 2000 وحدة قد تكون أكبر من الطاقة اليومية الفعلية للحساب؛ يجب قياسها قبل أي وعد عام.
